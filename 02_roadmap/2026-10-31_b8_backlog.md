final whole-branch review, the blind verifier and the live runs on the laptop. Every line here was
judged Minor or out of the B8 spec; none blocks the merge. Evidence and rulings:

## Seen live on the laptop, not changed

- Controls switch off when BurnMon Dev's launching shell has exited: the B4 self-check walks the
  ancestor chain, a dead parent makes it "incomplete" and every control goes off (the gear says why).
  A start from Explorer or a shortcut is not affected. Decide whether a dead parent may count as a
  complete chain when the pid is not reused.
- The gate controls run under the first `python` on `PATH` (`controls.ResolvePython`); on the owner's
  laptop that is the Hermes venv's `python.exe`. It worked (`-I`, Foreman's lib is standard library
  only), but a `python_path` setting or `py -3` would make it deliberate.
- A hidden Claude Code daemon session (`claude.exe daemon run`, `--bg-pty-host`, not listed by
  `claude agents --json`, not even with `--all`) shows as Your turn through the `claude_pids` source
  (`.claude\sessions\<pid>.json` with `kind=bg`).
- A stopped background agent keeps a Your turn row from the session store until that item ages out;
  the agent view part drops it at the next poll.
- Toasts leave nothing in the Windows notification center: the tray icon is deleted on timeout and
  hide (`NIM_DELETE`), and Windows drops the notification with it.
- Stale `HKCU\Control Panel\NotifyIconSettings` entries stay behind for every exe path that showed a
  toast (Windows never prunes them); the tray ids are bounded to 1 and 2 per exe since 850836b.
- Go plus WebView2 together used 2.46 percent of the machine over 3 idle minutes (renderer 51.7 s,
  Go 28.1 s, GPU 7.4 s of 180 s), above the 2 percent BurnMon's own advisor applies to that total.
  B8's share is unknown: no pre-B8 baseline under the same conditions.
- Not measured: `burnmon.exe` CPU with its new Foreman watch; latency for a gate written under
  `flows` (the harness writes a sprint's `sprint.json`).

## From the task and final reviews (all Minor)

Agent view and shim (Tasks 1, 2):
- "the claude.cmd shim cannot be read" drops the OS error; wrap it with `%w`.
- A `claude.exe` that is a link or a folder reads "does not exist" (the Lstat check was mandated).
- `%DP0%` in upper case and `%~dp0node_modules` (no separator) are handled but untested.
- resolve_test.go:21 `C:\n\claude.cmd` passes because the file is unreadable, which depends on the host.
- Class `dim` has no effect in the Waits body, so the agent view line renders in normal colour.
- The line names `burnmon.json`, but loadConfig also falls back to `claudecost.json` (legacy installs).
- README restart advice misses BurnMon Dev taking the lock while `burnmon.exe` restarts.

Watcher and Foreman watch (Tasks 3, 4):
- `match` runs on the Windows I/O goroutine before re-arm; document that it must be cheap; a nil
  `match` panics in the reader goroutine.
- Windows passes folder paths to `match`, fsnotify drops folders; the OnChange "a file" wording relies on callers.
- `TestWatchFilesStop`'s no-fire-after-stop check can hardly fail; a missing root logs twice.
- `w.kick` is written in Run without sync (current callers are ordered).
- The no-flows subtest does not show that a sprints change still kicks a write.
- Backend log lines say "full rescan" fallback; for Foreman the fallback is the 7.5 s read.
- Deletes and folders created after start do not kick (they wait for the 7.5 s read); the README
  slightly oversells.
- foremanwatch_test.go:238-239 comment overclaims; the span guard cannot tell load from a blocking
  Trigger; `TestCoalescerStreamStillFires` fails correct code after one 160 to 180 ms stall.

Page tick (Task 5):
- A full secPoll and redraw about twice per 5 s (age_seconds changes the JSON every poll); fix: the
  5 s timer skips when a secPoll ran in the last 4 s.
- A first snapshot written between the first secPoll and the first stamp waits up to 5 s.
- The stamp is stored before the read, so a hidden or failed read waits for the 5 s fallback.
- `TestSnapshotStampBinding` pins exact whitespace.
- With the overall scrollbar off, each 1 s tick writes scrollTop 0 then restores it, which can cut a
  smooth wheel scroll by one notch per second (inferred).

Harness and CPU script (Task 6):
- `idlecpu.ps1` divides by the requested minutes, not the measured window; its restart check compares
  ProcessName only.
- The harness output does not name the snapshot writer process.
- `build.ps1`'s `go mod tidy` rewrites `go.mod` to LF on every build.
- A Ctrl+C during the final cleanup or the last waitRow is not fully caught (no fake sprint is left either way).

Titles and Done group (Tasks 7, 8):
- An agent-view entry with an empty Cwd drops the folder the graph node already knows.
- `TestCountOf` checks titles by position; look items up by ID.
- README "the same for sessions started a minute apart" is slightly absolute.
- Out of scope: `internal\report\template.html:1744` labels sessions with `id.slice(0,8)`.
- d37's whole-panel chip counts no longer include the two Done rows; d44 checks the Done text only at the start.
- The focus ring may be clipped by `.seclist` overflow (inferred).
- README "starts collapsed at every start" repeats itself.
- A single-package `go test` printed `unlinkat ... burnmon-dev.test.exe: Access is denied.` after ok
  (a locked temp binary).

Toast (Tasks 9, 10, final review):
- No test for a suppressed re-entry that stays past its window.
- rules.go:86-88 comment reason is off; `oneLine` folds Cc runes only (U+202E, U+200B pass);
  `cut` can leave a space before the dots.
- Unchecked PostMessageW in Show and Close (practically unreachable).
- A failed first agent view poll passes the first-poll guard, and the next good poll's agent items fire
  once as a batch; a failed poll drops agent items for one period, so they re-toast (Ruling 19: 0
  agent view errors in 64 live snapshots).
- `TestToastWiring` greps main.go source text.
- The watch reads `burnmon-dev.json` without FILE_SHARE_DELETE; a gear save in that read fails (rare).
- Hermes and Copilot pollers first ingest at +5 s, outside initialCollectDone.
- A broken `burnmon-dev.json` logs "parse error" on every new snapshot.
